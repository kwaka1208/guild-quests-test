# Contributing to Guild Quests

Thank you for helping! This guide explains how to send a contribution.
Please read it before you open a pull request.

## Ways to contribute

- **Report a problem.** Open an issue with the **Bug report** form.
- **Fix a problem.** Fix a typo, a broken link, or a confusing sentence.
- **Pick a good first issue.** Issues labeled `good first issue` are small tasks for new contributors.
- **Create a quest.** Later in the course, you can propose a new quest.

## Before you start

1. Check that nobody else is already working on the same thing.
   Look at the open issues and pull requests.
2. If you want to work on an issue, leave a comment like this:

   > I'd like to work on this.

   Wait until the maintainer assigns the issue to you.

## How to send a pull request

1. **Sync your fork** on GitHub, then run `git pull`.
2. **Create a branch** for your change. Use a short name that describes it:

       git switch -c fix-typo-quest-00

3. **Make your change.** Keep it small. One pull request should fix one thing.
4. **Commit** with a message in the [Conventional Commits](https://www.conventionalcommits.org/) style:

       git commit -m "docs: fix a typo in quest-00 README"

5. **Push** your branch to your fork:

       git push -u origin fix-typo-quest-00

6. Open your fork on GitHub and click **Compare & pull request**.
7. Fill in the pull request template. If your change fixes an issue, write `Fixes #12`.

## Pull request title

The title must follow the same style as a commit message:

| Type | When to use it | Example |
|---|---|---|
| `docs` | Changes to text | `docs: fix a broken link in quest-01` |
| `fix` | Fixes to a bug in a quest | `fix: correct the stage 2 question` |
| `feat` | A new quest or a new feature | `feat: add a quest about error messages` |

A check runs automatically on every pull request.
If it fails, open **Details**, read the message, and push a fix to the same branch.

## Files you should not change

These files are generated by the maintainer. Pull requests that change them will fail the check:

- `quest-*/quest.py`
- `quest-*/stages.json`
- `.github/`
- `LICENSE`

If you think one of them has a problem, open an issue instead.

## Rules

- **Do not post answers or flags** in issues or pull requests.
- **Do not write private information**, such as your real name or your school.
  Everything here is public.
- **You must understand your own change.** You may use translation tools or AI to help you,
  but you must be able to explain every line you changed. The maintainer may ask you about it.
- Follow our [Code of Conduct](CODE_OF_CONDUCT.md).

## Review

The maintainer will review your pull request. You may get comments like these:

| Comment | What it means |
|---|---|
| LGTM | "Looks good to me." Your change is accepted. |
| Nit: ... | A very small suggestion. Fix it if you can. |
| Could you ...? | A request to change something. |
| Changes requested | You need to update your pull request before it can be merged. |

To update your pull request, push new commits to the same branch.
You do not need to open a new pull request.
